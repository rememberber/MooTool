## 2. 必须优先修复的问题

### R01 · P1：Release 版本跳过全部 DesktopHost 通信

位置：`lib/core/desktop/desktop_host.dart:48–74`。

`_listenIfPossible()` 与 `_channelReady` 用 `BindingBase.debugBindingType() != null` 判断通信是否可用。当前 Flutter SDK `foundation/binding.dart:423–425` 明确说明：该方法在 Release 中始终返回 `null`。应用虽在 `main()` 初始化了 binding，Release 仍会直接跳过注册监听和 `_invoke()`。

影响：托盘策略、截图、屏幕取色、图片剪贴板、防休眠以及关闭动作通信全部被跳过。macOS `MainFlutterWindow.swift:140–150` 默认关闭行为为询问，原生发送 `closeRequested` 后返回 `false`；Dart 又没有监听，关闭按钮便没有后续处理。

修复：依据真实 binding/messenger 初始化状态建立通道；测试环境通过依赖注入替换，不使用 debug-only API 控制业务功能。错误应能区分不支持、无权限与原生调用失败。

验收：**实际 Release 安装产物**验证托盘、关闭 ask/hide/quit、截图取消/成功、取色、图片粘贴、防休眠。MemoryDesktopHost 单测不能替代这一步。

### R02 · P1：编辑已保存笔记会让全局写入队列死锁

位置：`lib/app/app_controller.dart:420–448`、`:1017–1034`。

`persist()` 将 `_persistNow()` 排入 `_writeQueue`；笔记内容变化时，`_persistNow()` 等待 `_exportNoteFile()`；后者又把导出排在当前 `_writeQueue` 后面。形成“当前保存等待排在自身后面的导出”的循环依赖。

复现：创建并保存 `ORIGINAL` 笔记，编辑成 `CHANGED BY TYPING`，再保存。探针在 2 秒后超时。正常保存应很快完成；这里没有能够解除相互等待的后续事件。

影响：此后设置、工作区、自动保存，以及依赖 `persist()` 的备份、恢复和关闭流程一起卡住。

修复：只在最外层串行排队；队列任务内部直接执行实际文件写入，不再次入同一队列并等待。保存完成后再标记对应 revision 已保存。

验收：连续编辑与自动保存 100 次、交错修改 JSON/设置、自动保存期间关闭，均可完成；重新加载最后一次正文及元数据。

### R03 · P1：恢复备份后内存未更新，下一次保存覆盖恢复结果

位置：`lib/app/app_controller.dart:1456–1464`。

`restoreBackup()` 只替换磁盘内容并显示完成，仍保留恢复前的 settings、workspace、Vault 和各工具会话。后续自动保存会把旧内存写回恢复后的文件。

复现：备份浅色主题与快照正文 → 改成深色及另一份正文 → 恢复 → 保存。磁盘主题仍为 `dark`，预期是 `light`。

修复：暂停自动保存，等待在途任务，验证快照，在可回滚事务中恢复，再用快照重建内存及服务状态，最后恢复保存。恢复失败时保留恢复前数据。底层恢复也需验证 schema、完整性及缺失项，不能直接逐个覆盖并删除目标目录后才发现错误。

验收：恢复后不退出直接查看、修改一项设置、重启，所有声明覆盖的数据都停留在正确快照；损坏/部分缺失快照不破坏当前工作区。

### R04 · P1：导入新 Markdown 会覆盖当前已有笔记

位置：`lib/app/app_controller.dart:951–959`，关联 `:801–804`。

导入先把 `note.document` 改成导入内容，再调用 `createNoteDocument()`；后者看见旧 `documentId` 与 dirty 状态，先调用 `saveNoteDocument()`。此时保存到旧笔记的已是新导入正文。

复现：已有 `old.md` 内容 `ORIGINAL NOTE`，导入另一个 `imported.md` 内容 `IMPORTED NOTE`。导入后旧文档也变成 `IMPORTED NOTE`，探针已确认。

修复：先保存/保留当前文档，再创建新的独立笔记会话并装入导入内容、元数据和撤销栈。导入过程中不要复用仍指向旧文档的可变模型。

验收：旧文档干净/dirty、有/无 frontmatter、有附件等情况导入后原文均保持，且新文档单独存在。

### R05 · P1：切换 JSON 文件后撤销会插入另一份文档

位置：`lib/app/app_controller.dart:747–760`。

`openJsonDocument()` 复用同一个 EditorDocument，只用 `recordUndo:false` 替换文本，既没有为各文档保留独立撤销栈，也没有清空旧栈。

复现：打开 A=`{"a":1}` → 改成 `{"a":2}` → 打开 B=`{"b":1}` → undo。B 变成 `{"a":1}`。下一次保存可能把串入的正文写入 B。

修复：按 documentId 管理独立编辑会话和撤销历史；最低限度在切换时重置历史，且明确与跨切换保留 undo 的目标差距。

验收：A/B 交错编辑、撤销、重做和自动保存，不得跨文档作用。通过真实键盘快捷键补一条 Widget/集成测试。

### R06 · P1：一次写入失败会使后续所有保存失效

位置：`lib/app/app_controller.dart:420–425`、`:452–455`。

`_writeQueue.then(...)` 只有成功分支，保存失败又被重新抛出。队列进入 error 状态后，下次 `persist()` 沿用失败 Future，不再执行新的写入。`storeError` 还会让 Workbench 用错误文字替换整个工作区，没有可用的恢复操作。

复现：临时把 `settings.json` 路径设成目录，第一次保存失败；移除障碍后再次保存，仍抛同一次文件异常。

修复：调用方收到本次错误，但队列尾部必须恢复到可继续执行状态；保留未保存标记，提供重试/另存/导出，成功后解除错误状态。处理 debounce 的 unawaited 异常。

验收：只注入一次权限/磁盘写入错误，恢复条件后无需重启即可保存最新数据。

### R07 · P1：Git Token 与代理密码明文进入配置和备份

位置：`lib/app/settings.dart:255–256`；`lib/core/storage/snapshot_backup.dart:9–38`。

`toJson()` 直接输出 `gitToken`、`proxyPassword`，配置自动落盘后也被备份。界面输入框遮挡不会改变存储结果，目录权限也不满足原开发文档中的凭据存储约束。

复现：用虚构 token/password 序列化，两个敏感字段均存在于 JSON。

修复：使用本产品专属的系统凭据存储命名空间；普通设置仅保存凭据引用。迁移时清理配置及 `.prev` 中旧值，并明确历史备份处理方式，避免再次导出明文。

验收：保存、备份、导出、日志及迁移产物均不含测试凭据；并存产品的凭据引用不互相覆盖。

### R08 · P1：PDF 拆分/合并实际是样例文本重建，不保留 PDF 页面

位置：`lib/core/samples/simple_pdf.dart:30–57`；生产调用位于 `lib/features/pdf/pdf_service.dart`。

实现把整个文件按 UTF-8 解码，以正则提取 `(text) Tj`，将每个文本片段当成一页，再用固定 Helvetica/页面大小重新生成 PDF。真实页面的图片、矢量、字体、页面尺寸及多个文本指令都无法保留。函数也没有真正验证输入一定由 SimplePdf 生成，可能接受一部分普通非压缩 PDF 后输出错误结果。

复现：连自身生成的 `SimplePdf(['Hello (world)'])` 都无法读回，因转义括号被解析正则排除，抛出 `No extractable text pages`。

修复：生产拆合使用能够复制真实页面对象和资源的 PDF 实现；SimplePdf 留在测试夹具范围。暂未支持的文件必须在生成结果前明确拒绝，不应宣称已经正确拆合。

验收：真实多页 PDF 包含文字、中文、图片、矢量、不同页面尺寸，拆分再合并后页数/顺序/内容正确且文字仍可提取。不能只用 SimplePdf 自产文件验证。

### R10 · P1：JSON 自动保存先落盘旧 Vault，后更新内存并标记已保存

位置：`lib/app/app_controller.dart:431–439`。

`workspace.json` 在更新当前 VaultDocument 之前就已写入。随后只修改内存中的文档正文并 `markSaved()`，没有第二次写盘。

复现：文档 version=1 保存 → 编辑 version=2 → 等一次自动保存 → 新控制器加载。编辑草稿可能是 version=2，但 Vault 文档仍为 version=1；重新从树打开该文档可取回旧正文。

修复：先形成一致的会话/Vault 快照，再持久化，写成功后按 revision 确认已保存。避免编辑草稿和 Vault 的两个事实来源不同步。

验收：最后一次修改后只执行一次自动保存立即重启，再从文件树打开，正文和查询等元数据必须一致且是最新版本。

### R11 · P1：分离窗口按钮并未创建真实窗口

位置：`lib/app/app_controller.dart:1759–1790`；`lib/features/workbench/workbench.dart:251–260`。

`detachTool()` 仅在同进程协调器中自行 ack 并加入集合，没有调用创建 OS 窗口/Flutter engine 的实现。主工作区随即隐藏工具，只显示“已分离/收回”。用户没有第二个窗口可以继续操作。

这属于核心功能缺失，不是视觉调整。`p7-gap-review.md` 的“同 engine 占位”说明不应被误读为已支持可用的独立窗口。

修复：完成真实窗口生命周期、初始化确认、失败回滚及会话转移；未完成时不要将工具标记为已成功分离。

验收：JSON、随手记、HTTP、计算器同时分离，真实存在多个窗口；文本/选区/undo/运行任务保持；关闭子窗口正确收回；重复 100 次无遗留窗口或双写 owner。

### R13 · P1：停止代码运行只杀父进程，子进程继续运行

位置：`lib/features/runtime/runtime_service.dart:151–153`、`:176–184`。

`cancel()` 只向启动的 Process 发 TERM/KILL，没有管理整个进程树。父进程退出后超时计时器被取消，但代码仍等待 stdout/stderr 完成；如果子进程继承管道，运行 Future 也会继续挂住。

复现：Python 任务创建一个等待 30 秒的 Python 子进程，点击等效取消后等待 1.6 秒，`kill -0` 仍能确认子进程存活。本轮探针随后自行终止该子进程。

修复：采用平台适配的进程组/Job 等机制，取消整棵受控进程树；同时管理输出订阅、超时与临时文件清理，不把父进程退出当成任务全部结束。

验收：父进程、子进程、孙进程以及忽略 TERM 的任务都在限制时间内终止；之后可立即运行新任务且没有残留进程/管道/临时目录。

## 3. 其他已确认缺陷

### R09 · P2：正则全局匹配改变了锚点语义

位置：`lib/features/regex/regex_engine.dart:65–74`。

通过不断截取 `source.substring(index)` 再执行 `firstMatch`，每轮都产生新的字符串开头。`^a` 在 `aaa` 上返回 `[0,1,2]`，正确结果是 `[0]`；前文相关的匹配也会失去上下文。应在原字符串上执行全局匹配，并测试锚点、前后断言、零宽、Unicode 和 multiline。独立补上耗时匹配的隔离/超时机制。

### R12 · P2：查找只改模型选区，没有移动编辑器可见选区

位置：`lib/design/widgets.dart:49–65`；查找入口 `lib/features/json/json_tool.dart:228–237`。

`didUpdateWidget()` 只在文档对象或正文变化时同步控制器。查找只调用 `restoreView()`，正文不变，因此跳过更新。Widget 探针将 `alpha beta gamma` 的模型选区设为 `[6,10]`，实际 TextField 仍折叠在 0。

修复时需同步选区和滚动，并保护输入法 composing 状态；验收查找下一项、反向选区、跨屏匹配、切文档与中文输入组合场景。

### R14 · P2：所谓原子写入先删除原文件，存在断电/崩溃空窗

位置：`lib/core/storage/atomic_file.dart:12–16`、`:32–34`。

代码先复制 `.prev`，再删除主文件，最后 rename 临时文件。若删除后中断，下次 `readJsonObject()` 把主文件缺失当作“尚未配置”，不会加载 `.prev` 或进入恢复流程，后续保存可能写入默认工作区。

此项为代码路径确认，未进行真实断电实验。应使用目标平台可靠的替换协议和启动恢复机制，验证在写入各步骤故障时至少保留一份可恢复版本；同产品多进程还需要互斥和临时文件冲突处理。

### R15 · P2：自定义数据目录不能保证其他产品不受影响

位置：`lib/app/app_controller.dart:272–276`；`lib/app/app_paths.dart:54–89`。

默认路径和产品标识是独立的，这部分方向正确。但 `load()` 先 ensure/chmod，之后才验证隔离；验证只按少量目录名字匹配，不检查已有 `product.json` 所属产品，也不解析真实路径，且未覆盖 Java 使用的 `.MooTool`。

复现：在临时目录模拟 `.MooTool` 并写入其他 productId，加载没有拒绝，已创建 Flutter 子目录。**触发条件是指定错误的自定义数据目录；本轮没有发现默认启动自动访问其他产品目录。**

修复：所有写入之前解析并校验 canonical path、产品标记及必要的目录边界；不改动其他产品目录权限；导入仍采用独立的只读来源流程。验收覆盖真实路径、symlink、同名目录、外产品标记和错误配置。

### R16 · P2：导航缺少正确的 Material 绘制层，交互反馈被遮挡

位置：`lib/features/workbench/workbench.dart:96–100`、`:212–235`。

ListTile 位于不透明 ColoredBox 下，背景/ink 绘制却落在更外层 Material。当前 SDK 在两种尺寸的全部页面检查中报告 `ListTile background color or ink splashes may be invisible`。

修复：为实际可交互区域提供正确的 Material/Ink 层，同时补充选中、hover、pressed、focus 状态。另见截图：默认侧栏底部的 `MooTool` 被语言按钮挤成逐字竖排，应重排底栏、约束按钮实际点击尺寸与文本最小空间。

### R17 · P2：调整 UI 字号在当前 SDK 调试模式中触发主题断言

位置：`lib/design/theme.dart:251–255`；设置入口 `lib/features/settings/settings_page.dart:250–257`。

对 `ThemeData(...).textTheme` 直接调用 `apply(fontSizeFactor: uiFontSize / 13)`，当前 SDK 中部分 TextStyle 的 fontSize 为 null。默认 13 不触发；字号改成 14 时触发 `TextStyle.apply` 断言，主题构建失败。独立探针已复现。

修复：从已解析、字体尺寸完整的排版体系构建主题，或逐项提供明确字号，再应用缩放。不要用关闭断言掩盖。需分别验证 debug/release 的 11–18 字号、主题切换与持久化后的启动。

## 4. R18：macOS 构建复核记录（不计入代码缺陷）

原工作区中两种命令均出现链接失败：

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  /Users/zhoubo/sdk/flutter/bin/flutter build macos --release --no-pub
./scripts/package.sh macos
```

核心错误为 `FileSelectorPlugin.register`、`UrlLauncherPlugin.register` 及类型元数据符号未定义。检查时生成的 `macos/Flutter/ephemeral/Packages/FlutterGeneratedPluginSwiftPackage/Package.swift` 的 dependencies 列表为空，但 GeneratedPluginRegistrant 仍引用这两个插件。
