# MooTool Next Flutter 验收与交付标准

> 初始状态：全部待开发/待验收。本文规定测试方法和完成标准，不能作为已通过的测试报告。

## 1. 状态与证据规则

| 状态 | 何时使用 |
| --- | --- |
| 未开始 | 没有对应实现 |
| 开发中 | 有部分实现，核心路径尚未闭环 |
| 待验收 | 代码完成但缺真实平台/视觉/持久化证据 |
| 已验收 | 本文要求的对应范围已执行，并链接具体证据 |
| 明确差异 | 有精确范围、原因、替代操作、影响及决策记录；不自动视为完整对齐 |

禁止以“库声称支持”“页面有按钮”“另一个版本已通过”“构建通过”代替用户流程验收。未运行的平台标记未验证；预览版可以有限范围发布，不能称三平台完整可用。

每轮证据放入 `docs/evidence/<日期>-<阶段>/`：

```text
environment.md       # 提交、工具链、OS/架构、屏幕缩放、测试数据路径
results.md           # 检查命令、结果、失败和范围
screenshots/         # 当前产品可复现截图
parity.md            # 当前 Electron 基线、Flutter 变化、未决项
performance.json    # 如本轮有性能测试，含原始测量
```

测试不能使用开发者真实工作区。应用内集成测试启动参数指定 Flutter 临时数据目录；Electron 对照运行使用另一个专属临时目录。测试后只清理自己创建的目录。

## 5. 视觉验收

### 5.1 建立两类基线

1. **Electron 体验基线**：冻结提交、设置、测试数据、窗口尺寸。检查工具顺序、左右/上下关系、Tab 顺序、主要动作和结果位置。
2. **Flutter 视觉基线**：按现代 token 和本平台原生行为建立。检查字体、色彩、边距、焦点、密度和主题一致性。

Flutter 不要求与 Electron 跨渲染引擎逐像素相等。外边距、圆角、原生按钮和字体渲染等有意变化记录为设计差异；不能借此容许布局错位、缺功能或错误选中态。

每张截图写明版本/提交、系统、DPI、logical size、语言、主题、导航模式、工具状态。历史截图中的大标题不再作为当前功能页验收目标。

### 5.2 矩阵

| 维度 | 最低覆盖 |
| --- | --- |
| 入口 | 26 个入口默认态全部覆盖；有编辑/结果的工具至少一个真实结果态 |
| 主题 | 每个入口 light/dark；另测系统主题切换 |
| 核心尺寸 | 1440×920 light、1080×720 dark；JSON/随手记/HTTP/设置两尺寸双主题 |
| 额外尺寸 | 960×640 最小、1920×1080 大屏；实际平台支持允许更严格最小值但需记录 |
| 语言 | 中文/英文/日文导航和设置全量；密集工具全部检查英文/日文最长文案 |
| 缩放 | 至少 100%、150%、200% OS 缩放；应用文字 125%、150% |
| 导航 | classic/card/grouped、展开/折叠、自定义组/隐藏工具 |
| 风格 | modern 完整矩阵；其余五个预设至少首页/JSON/设置的双主题代表状态 |
| 原生层 | 工具独立窗口、原生菜单/文件对话框、tooltip、popup、拖放反馈 |

验收标准：

- 功能工作区贴齐可用区域，无额外大标题/装饰卡片占据编辑空间。
- 主操作可见，工具栏不裁切；无黄黑 overflow、重叠、空白渲染或窗口级横向滚动。
- 表格、编辑器、树和菜单各自滚动，footer/主要操作不跟随长列表消失。
- 深色弹窗、原生 titlebar、代码语法和选中文本清楚；焦点框可辨。
- 空白/无权限/错误状态有行动入口；“无数据”不覆盖“加载失败”。
- 图标按钮有语义标签和 tooltip，键盘可走完整流程；VoiceOver/Narrator/可用 Linux 读屏进行代表场景检查。
- Golden 更新必须审阅差异；禁止盲目批量接受新截图消除失败。

### 5.3 黄金路径截图场景

- JSON：格式化后、重复 Key、JSONPath 树、查询结果、查找替换、Git diff、窄检查器。
- 随手记：编辑/分栏/预览、列选区、快速替换、图片附件、正文搜索。
- HTTP：带参数的请求与真实响应、错误、取消中、保存集合。
- PDF/图片：任务排队、成功结果和单项错误。
- 设置：外观、布局、数据/备份、更新下载状态。
- 主壳：命令搜索、自定义组、折叠侧栏及多个分离窗口。

## 6. 性能与资源

以下是 Flutter 初版工程目标，不是当前测量结果；P0/P2 要记录参考硬件，调整目标需说明理由。用 release/profile 模式测试，debug 耗时不能当发行指标。

| 指标 | 初始目标 |
| --- | --- |
| 冷启动至导航与输入可用 | 中位数 ≤ 2 秒；至少 10 次，记录 p95 |
| 已加载工具切换 | p95 ≤ 100 ms，无输入丢失 |
| 普通文本键入反馈 | p95 ≤ 50 ms；不计输入法候选服务自身延迟 |
| 搜索 26 工具 | p95 ≤ 50 ms |
| 3 MiB JSON 格式化 | ≤ 3 秒；UI 可交互、可取消 |
| 5 MiB 随手记保存/恢复 | 单次 ≤ 2 秒；不阻塞 UI isolate |
| 10,000 文件树节点 | 首屏增量显示 ≤ 1 秒；虚拟化/后台索引 |
| 帧耗时 | 常见操作以 60 Hz 的约 16.7 ms 帧预算检查；记录慢帧和原因 |
| 稳态内存 | 主窗口+已使用核心工具参考目标 ≤ 300 MiB RSS；跨平台分别测量 |
| 反复窗口转移 | 100 次后无持续单调增长；关闭临时引擎/worker 后稳定值有记录 |

性能不作为伪造测试数字或删除功能的理由。多 engine 内存成本高时采取按需创建、及时释放非 owner engine 和有限缓存，不能销毁 dirty 会话。

压力样本包含：1/3/10 MiB JSON、5 MiB 笔记、大段单行文本、10,000 节点 Vault、20 项 PDF、超大图片、连续网络取消和无限运行程序。所有限制使用统一常量，超限告知原因并保留现有数据。

## 7. 五产品并存：专门验收

测试环境同时安装可用的 Java、Electron、Tauri、macOS Native（仅 macOS）和 Flutter。缺少某产品时记录未覆盖，不能默认判定通过。

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| ISO-01 | 安装 Flutter | 应用名、ID、目录、快捷方式、卸载项独立；其他安装文件 hash 不变 |
| ISO-02 | 所有可用产品同时启动 | 不被跨产品单实例锁阻止；不激活错误产品 |
| ISO-03 | Flutter 修改主题、草稿、历史、Vault | 其他产品专属数据内容不变，重启仍保持原设置 |
| ISO-04 | Flutter 更新检查遇到其他产品更高版本 | 不提示跨产品升级，不下载其他产品资产 |
| ISO-05 | 安装 Flutter 新版本 | 仅升级 Flutter，自有数据迁移成功 |
| ISO-06 | 卸载 Flutter | 其他产品可启动且数据不变；删除 Flutter 数据只在明确选择时发生 |
| ISO-07 | 从 Electron/Java 显式导入 | 来源内容 hash 不变，旧产品仍正常使用 |
| ISO-08 | 用户误选其他产品活动数据/Vault 目录 | 阻止直接接管，提供复制导入方式 |
| ISO-09 | 凭据和缓存 | Flutter 专属命名空间，不能读到/删除其他产品 token |
| ISO-10 | 只取出 next-flutter 干净构建 | 不读取其他产品源码/资源/产物，不运行其他产品构建 |
| ISO-11 | 发布 Flutter tag/更新清单 | 只操作 next-flutter 节点和 Release；保留其他节点，不覆盖 Latest |
| ISO-12 | 平台 URL scheme/文件关联/全局快捷键 | 独立身份；默认不抢占已有产品注册；冲突时显式提示 |

ISO-03 验证专属数据的只读/未改写，可对关闭的来源数据制作 before/after 内容 hash。测试运行中数据库自行写 WAL 时不能把其正常写入误判为 Flutter 改动；需要控制测试条件并辅以实际访问日志。

系统 Hosts、环境变量、剪贴板属于 OS 共享资源，用户主动操作它们会影响整个系统。验收应确认“操作范围明确、动作由用户触发、没有跨产品私有数据依赖”，不能要求剪贴板或系统 Hosts 在不同应用间物理隔离。

## 8. 发布和更新验收

- 每个发行平台实机安装、首次启动、升级、取消更新和卸载。
- 版本/ID/tag/notes/文件名一致；没有未打包的 DLL、资源、helper。
- stable 不收到 beta/rc；预发布接收规则有测试。
- 缺失产品节点、空 releases、坏 JSON、未知 schema、无匹配架构和断网都能正常反馈。
- 下载取消、断开网络、空间不足、hash/长度错误不进入“已就绪”。
- 下载产物只属于 Flutter；手动安装模式显示正确动作，不能显示并未支持的“自动安装成功”。
- 更新/备份/退出遇到 dirty 文档先完成保存或让用户处理失败，不直接丢草稿。
- 资产可访问后才更新产品清单，其他节点 byte/结构内容保持不变。
- 发行说明写清平台支持、未签名状态（如适用）、明确差异和产品独立关系。

- [ ] 当前 Electron 沉浸布局、设置页、列编辑、图片转 SVG 等新基线没有被旧截图覆盖。
- [ ] 三语言、明暗主题、键盘/IME、默认/紧凑布局和平台原生操作通过。
- [ ] 编辑器撤销、自动保存、文档切换、附件和大文本可靠。
- [ ] 多窗口 session 转移、关闭收回、任务继续/取消及错误回滚通过。
- [ ] 数据 schema 迁移、损坏保护、备份恢复、显式导入和只读来源通过。
- [ ] 算法使用真实实现，复杂能力已有语义/跨实现 fixtures。
- [ ] 已发布平台的实际原生能力、权限、DPI、安装包和更新闭环通过。
- [ ] 五产品并存范围有独立报告，数据/安装/更新/构建没有隐式耦合。
- [ ] 性能指标有真实测量，限制与未覆盖平台如实记录。
- [ ] Flutter 自有版本、Release notes、许可证、更新节点和 Latest 策略符合约定。
- [ ] 不含伪成功按钮、隐藏 TODO 流程、发布态 mock 数据或未披露的功能删减。

若只是阶段预览，应按实际范围命名并发布；不要把“做完 P1 壳”标记为完整 Flutter 版。
