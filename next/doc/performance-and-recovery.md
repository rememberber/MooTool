# 后台计算、首屏加载与工具恢复

## 保留的设计

工具打开后继续保留其 WebContentsView，普通切换和拆窗不卸载视图。正则和计算器仍按原有方式写入 localStorage 与数据库；历史列表仍返回完整记录。本次不调整这些存储和生命周期策略。

## 文本计算

- JSON 格式化、压缩、转换和 JSONPath 查询，以及文本对比，复用既有函数，在 renderer 的模块 Web Worker 中执行。
- 50,000 字符以下的 JSON 保留即时校验；更大的输入停止输入 150 ms 后在 Worker 中校验，待处理时显示“处理中”。关闭的路径选择器不解析文档。
- 每个计算任务独占一个 Worker，输入改变、新任务、取消或页面卸载时终止旧任务。结果同时检查输入版本，过期任务不改写当前内容或写入历史。任务最多运行 60 秒，失败显示错误。
- 文本对比初次打开不在界面线程计算已恢复的大草稿；实时对比与显式对比均走后台任务。取消不清空输入。

## PDF

文件检查、合并和拆分均由 `pdfWorker.js` 执行，主进程只负责窗口、参数校验、任务管理与最终文件提交。PDF 操作每个 WebContents 同时最多一个；进度和取消绑定任务 ID 与发起者。关闭发起者、renderer 崩溃或退出应用时取消其任务。

Worker 只写入临时目录。全部计算成功后，主进程先将文件复制到目标目录的临时文件，再以 rename 提交，保持原来的输出路径和覆盖规则。取消时会终止 Worker、清理暂存内容，不改写目标文件。提交阶段短暂禁用取消，避免误报取消成功。每个文件的提交是原子的；多文件提交发生磁盘错误时，已经提交的文件不会回滚，因此整个批次不是事务。

进度按文件报告；单个 PDF 的内部解析没有细粒度进度，但仍可取消。无法保证恢复崩溃前尚未持久化的编辑内容。

## 工具恢复

renderer 意外退出后重载同一 WebContentsView，保留停靠位置、独立窗口和尺寸。30 秒内第一次崩溃自动恢复；再次崩溃停止自动重试，显示原生错误对话框与重载操作。主工作区也显示重试入口。已保存数据由各工具现有机制恢复，不引入新的草稿保存策略。

## 加载与构建

主工作区、工具窗口、截图和取色窗口、设置页面按需加载；CodeMirror 语言包在对应编辑器需要时加载，在 renderer 内合并并发加载并缓存，使用 Compartment 应用语法，不重建编辑器。大文档仍按原有阈值禁用富语法支持。

main、preload、renderer 均启用生产压缩。模块 Worker 使用 ES 输出，使 Worker 内的按需导入能正常打包。

2026-10-17，macOS arm64 源码构建，对比当前改动与 Git HEAD（`4b6674d1`）的隔离构建。用 Electron CDP 记录全新用户目录主页加载请求，等待主页显示后 300 ms，累计请求的本地 JS 文件大小（去重、未 gzip）：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| renderer HTML 入口 JS | 2,357,587 bytes | 444,305 bytes |
| 主页加载 JS 总量 | 2,367,247 bytes | 919,715 bytes |

总量包含拆分后主页实际请求的依赖，下降约 61%。这是代码加载体积，不代表启动耗时、进程内存或安装包缩减比例。7 月旧性能记录不作为当前版本的实测数据。
