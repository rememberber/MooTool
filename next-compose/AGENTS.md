# next-compose 开发约束

本文件只约束 `next-compose/`。用户在当前会话中的明确要求优先。

## 开始工作

1. 阅读 `README.md`、`docs/cursor-development-guide.md`，再读取本次涉及的 UI、功能、架构及验收章节。
2. 检查当前 Git 状态，保留用户及其他产品的未提交工作。只实施当前已授权阶段。
3. 首次开发记录真实版本组合和源码基线。工程建立前，不声称 Gradle 命令已通过。

## 产品与实现

- 这是独立 Compose Multiplatform Desktop 产品；UI 壳、导航、面板、设置和工具页面用 Compose 编写。
- 允许本产品内重复实现或复制有授权的代码，保留来源与许可证。不建立指向其他产品的源码、资源、数据库或运行时依赖。
- 桌面首选 Kotlin/JVM + 自带 runtime；它和 MooTool Java 产品是两个概念。
- 不导入根 Java 工程的 Swing Form。复杂代码编辑可经 `EditorHost` 使用本产品自己声明的 Swing 编辑组件；必须验证输入法、列编辑、弹层、DPI 与分离/收回。
- 保留首页 + 25 工具的入口/顺序及主要工作流，不用统一多行输入框代替所有页面。
- 计算、IO、网络、进程、Git、索引不能阻塞 UI/EDT；不可取消的第三方计算需进程隔离或明确资源上限。
- 状态属于工具会话，窗口只是宿主；重组、切页和窗口转移不得清空文档、撤销栈或在途任务。
- 所有应用身份、路径、锁、凭据、升级和卸载操作都使用 `next-compose` 自有命名空间。
- 不静默导入、修改或删除其他产品数据。用户主动导入使用只读源、预览、备份与事务。

## 完成标准

- 功能必须真实执行；按钮不能以固定提示、示例输出或空实现假装成功。
- 技术选型存在困难时先做有验收条件的小实验，不随意删需求；差异记录原行为、新行为、理由、证据和受影响范围。
- 适用的输入错误、取消、保存失败、缺少依赖和无权限状态必须可见。
- 使用当前阶段所需的单元、集成、UI 和真实安装检查；不得将编译成功描述为三平台验收通过。
- 更新 `docs/acceptance.md` 及证据目录，说明完成项、实际执行的检查、未测项和下一步。
- 本目录文档中的代码/命令若标为示意，落地时必须按锁定依赖验证并更新为真实用法。

本文件不额外要求为普通编码、可逆修改或本地检查征求确认；按用户已授权范围推进。
