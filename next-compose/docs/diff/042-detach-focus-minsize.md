# DIFF-042：分离窗口聚焦、侧栏分离入口与最小尺寸提示

- 编号：DIFF-042
- 影响：P1 壳/导航、A02 命令搜索、ui-spec 分离窗口与最小尺寸
- 日期：2026-09-15

## 原行为（Electron）

侧栏工具行有分离/收回按钮；打开已分离工具时主区显示占位并聚焦既有窗口，不新建第二会话。命令搜索同样打开该工具。窗口管理器把窗口压到 960×640 以下时仍保留关闭/搜索和滚动，并提示最小尺寸。首页不进入最近使用。

## 本产品行为

- `openTool` 始终切换主区会话。若该工具已分离，主区显示占位（定位窗口 / 收回），并向已有拆出窗发送聚焦请求（还原最小化、`toFront`）。
- 侧栏可分离工具：展开且未隐藏标题时显示 ⧉/▣；右键菜单提供分离/收回，已分离时可「定位窗口」。折叠侧栏仍可用右键。
- 最近使用最多 5 条，排除首页，点击当前项不重复。
- 内容宽高任一小于 960×640 时，工作区顶部显示最小尺寸提示，不挡住保存/退出。
- 关于页去掉「仅实现 modern」的过期说明；外观页写明六风格是 Compose token，不是 CSS 逐选择器皮肤。

## 理由

此前点击已分离工具只改状态栏、不进入占位页、也不前置拆出窗；侧栏没有分离入口，只靠各页工具栏按钮。规格要求「打开已分离工具时聚焦既有窗口」和「右键/显式按钮提供分离与收回」。

## 证据

`DetachPolicyTest`、`LayoutPolicyTest.minSizeHintWhenWindowManagerForcesBelowCompact`。`desktopTest` **217/217**，见 `docs/evidence/2026-09-15-detach-focus-minsize/`。真实窗口聚焦手势、960 截图、IME 手工、三平台安装仍未测。

## 受影响范围

- 聚焦依赖同一 JVM 内的 Compose `Window`；macOS 若被其他应用抢焦点，可能只把本进程窗口提到前面。
- 产品仍声明最小 960×640；提示只在窗口管理器无视下限时出现。
- 仍非 Electron 六套 CSS 逐选择器移植。
