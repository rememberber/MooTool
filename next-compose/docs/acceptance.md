## 3. 工程建立后应有的检查入口

以下预期基于 `composeApp` + `jvm("desktop")`。P0 先检查真实 Gradle task 列表，补齐脚本和测试源集，再更新本节；不要假装当前目录已可执行。

```bash
cd /path/to/next-compose
./gradlew --version
./gradlew :composeApp:tasks --all
./gradlew :composeApp:desktopTest
./gradlew :composeApp:run
./gradlew :composeApp:createDistributable
./gradlew :composeApp:runDistributable
./gradlew :composeApp:packageDistributionForCurrentOS
```

Windows 使用 `gradlew.bat`。各 OS 打包任务在该 OS 执行；不将 macOS 运行时跳过 Windows task 的结果记录为 Windows 构建成功。

测试层级：

| 层级 | 验证对象 | 不能代替 |
| --- | --- | --- |
| 纯逻辑/fixture | 算法、解析、模型、版本/路径、错误 | 输入法和真实文件系统 |
| 临时目录/DB 集成 | 设置、迁移、原子保存、WAL 备份、watcher、冲突 | 真正安装/卸载 |
| 受控网络/进程 | HTTP 参数、超限/取消、输出上限、停止后代 | 在线服务真实可达性 |
| Compose UI | 导航、语义、控件动作、焦点、状态、分栏 | Swing 编辑器内部节点完整覆盖 |
| Swing/原生集成 | IME、undo、列编辑、快捷键、弹层、拖放 | headless 单测 |
| 安装镜像/目标 OS | runtime、native lib、权限、identity、升级卸载 | `run` 或 IDE 预览 |

Compose UI 测试使用当前版本官方 JUnit API。Swing 控件需额外 adapter/真实桌面检查；不能仅断言 EditorHost 存在就宣布输入法和列编辑通过。Linux 图形测试可用虚拟显示跑基础流程，但 Wayland portal、真实屏幕和读屏另做实机测试。

## 5. 性能目标与测量方式

以下为初始工程目标，**不是测量结果或对外性能承诺**。P0 记录硬件、OS、架构、JDK、构建方式、数据尺寸和采样方法；目标可依据证据调整，不能未经说明放宽。

| 项目 | 初始目标 |
| --- | --- |
| 冷启动至首帧 | 发布镜像、本地磁盘，5 次采样中位数 ≤ 2 秒 |
| 冷启动至可输入 | 中位数 ≤ 3 秒，不等待所有工具/Git/网络初始化 |
| 已初始化工具切换 | 20 次采样 p95 ≤ 150 ms |
| 编辑延迟 | 常规文档按键到显示 p95 ≤ 50 ms；无持续 UI 停顿 |
| 3 MiB JSON 格式化 | 后台处理，目标 ≤ 2 秒；操作期窗口仍能移动/取消 |
| 5 MiB 随手记 | 目标 2 秒内打开可编辑；保存/预览不重置选区 |
| 长任务取消 | 普通任务 500 ms 内反馈，进程树 2 秒内终止或给实际失败 |
| 10000 文档目录 | 初次索引后台进行，后续搜索 p95 目标 ≤ 200 ms；树虚拟化 |
| 内存观察 | 记录空闲、打开多工具、转移窗口 20 次后的 RSS/heap；无持续增长趋势 |

不要用 debug/hot reload 内存代替发布版指标；不能只测平均值掩盖卡顿。文本字节数用 MiB 明确，文件分布、行长度、图片像素数与并发数同时记录。
