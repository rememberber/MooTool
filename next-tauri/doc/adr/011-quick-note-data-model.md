# ADR-011：随手记采用数据库优先模型

> 状态：已采纳  
> 日期：2026-08-18

## 背景

MooTool Next Tauri 与 MooTool Next Electron 是并行、独立演进的产品线。用户需要两者在“快速记录、检索、预览和带走内容”的核心任务上保持接近体验，但 Tauri 不以迁移 Electron 的源码、目录结构或工作区模型为目标。

## 决策

1. Tauri 随手记以产品自有 SQLite 为唯一实时数据源，笔记随完整备份一起进入 Tauri 产品的数据生命周期。
2. 编辑内容在停止输入 650 ms 后自动保存；保存中的快照通过前端修订版本保护，不得覆盖随后继续输入的内容。
3. 提供标题/正文搜索、查找替换、编辑/分栏/预览、置顶、复制、删除和文档统计，覆盖快速记录的主要任务闭环。
4. 用户可以通过 Rust-owned 原生文件对话框导入 UTF-8 文本或 Markdown，并把当前正文导出为 Markdown。Renderer 不接收任意路径读写能力。
5. 1.0 不复用 Electron 的外部笔记文件树、仓库路径、文件监控或 Git 自动操作，也不与 Electron 同时写入一个实时笔记目录。
6. 如果未来增加 Tauri 自有笔记工作区或 Git，同样使用 Tauri 自有目录、Schema、锁和领域命令，并作为本产品的独立功能演进。

## 结果

- Tauri 和 Electron 可以同时运行，不会争用笔记文件、数据库或 Git 自动任务。
- 用户仍可用显式导入导出交换单篇内容；跨产品实时共享不属于 1.0 能力。
- Electron 后续改变文件树或 Git 行为不会成为 Tauri 的兼容性约束。
