## 3. 检查命令契约

下面命令已在 P0 建立。macOS x64 `app-image` 与 `verify-package.sh` 本机 exit 0。Windows 打包入口存在但本机未跑。`./mvnw -Pui-tests test` 本机已跑过窗口转移；尚无 TestFX 页面用例。

| 命令（在next-fx执行） | 期望含义 | 首次建立阶段 |
| --- | --- | --- |
| `./mvnw -version` | 校验Wrapper/JDK/架构 | P0 |
| `./mvnw clean verify` | 编译、单元、服务集成及质量检查，不触碰真实用户数据 | P0起 |
| `./mvnw javafx:run` | 启动dev身份应用、独立dev数据 | P0 |
| `./mvnw -Pui-tests verify` | 真实显示环境的FX交互测试 | P0起 |
| `./scripts/package.sh --type app-image` | 本机runtime+app-image；脚本先实现参数/错误处理 | P0 |
| `pwsh ./scripts/package.ps1 -Type app-image` | Windows等价入口 | P0 |
| `./scripts/package.sh --type dmg` 等 | 对应本机安装包；不跨OS调用 | P7 |
| `./scripts/verify-package.sh <产物路径>` | 身份/版本/模块/架构/hash检查与启动smoke | P0起 |
| `pwsh ./scripts/verify-package.ps1 -Path <产物路径>` | Windows等价验证入口 | P0起 |

profile内测试有失败必须非零退出；缺显示服务/外部依赖应明确报告，不通过skip全部UI测试制造绿色。LinuxCI可用`xvfb-run -a ./mvnw -Pui-tests verify`（依赖先配置），真实IME和系统权限另测。

## 5. 性能预算

以下为P0/P7起始目标，非已有测量。基准机约4核/16GB/SSD、发行app-image、dev工具关闭；记录OS/CPU/内存/JavaFX渲染后端/输入大小。不能拿Electron开发模式与FX发行模式作结论。

| 场景 | 建议目标 | 测量方式 |
| --- | --- | --- |
| 冷启动可交互 | ≤3s | 进程启动至首页/导航接受输入，10次记录median/p95 |
| 已打开工具切换 | p95≤100ms | 30次切换至首帧可操作，保持文档状态 |
| 编辑器普通输入 | p95≤50ms，不连续冻结>200ms | 1MiB文档输入/粘贴/滚动和FX pulse/JFR |
| 3MiB JSON格式化 | ≤2s或始终有可取消忙态并记录偏差 | 固定fixture，不能降低正确性换速度 |
| 5MiB随手记 | 可打开/编辑/保存，无静默截断 | 记录打开/保存时延和最大内存 |
| 空闲首页 | CPU趋近0，无持续无意义轮询 | 稳定30s后采样60s，记录环境噪声 |
| 内存 | 首页RSS建议≤300MiB；超过需剖析/说明 | 不只看Java heap；WebView/native也计入 |
| 生命周期泄漏 | 50次开关/转移后无持续增长趋势 | heap/线程/handle/订阅基线对比，不能仅强制GC一次下结论 |
| 取消 | 点击后UI≤100ms响应；任务终止通常≤2s | 单独记录协作取消与worker强杀结果 |

不达目标先定位：无界任务、重复parser、全量setText、缩略图未释放、监听器未注销等。可以基于有证据的产品决定调整阈值，但不能直接删除失败行。
